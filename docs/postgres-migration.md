# PostgreSQL 18

Основное хранилище Смены — PostgreSQL 18. Для локальной работы используется существующий контейнер `postgres`, адрес `127.0.0.1:5432`, отдельные база и пользователь `smena`. Настройки других приложений не менялись.

## Запуск

Для нового окружения создайте отдельную базу и пользователя, затем скопируйте `.env.example` в `.env.local` и заполните `SMENA_DATABASE_URL`. Пароль хранится только в локальном файле, исключённом из Git. `npm run dev` и `npm start` читают его автоматически.

```bash
npm ci
npm run dev
```

Интерфейс разработки: <http://127.0.0.1:5173>. Для собранного приложения:

```bash
npm run build
npm start
```

Собранное приложение: <http://127.0.0.1:3001>. При старте приложение создаёт схему, применяет недостающие миграции и один раз добавляет 25 базовых предметов. Повторный старт не меняет настроенные предметы, администратора или школьные данные. Новая база не содержит демонстрационных групп, преподавателей и расписания; администратор создаётся через обычную первоначальную настройку.

`SMENA_DB_PATH` оставлен для явного запуска прежнего SQLite-контура и изолированных тестов. Явно заданный `dbPath`/`SMENA_DB_PATH` выбирает SQLite; явно заданный `databaseUrl` в коде выбирает PostgreSQL. Обычный локальный файл `.env.local` содержит только PostgreSQL-подключение.

## Перенос существующих данных SQLite

Перенос выполняется отдельной командой, а не при каждом старте. Источник должен иметь SQLite-схему версии 23. Целевая PostgreSQL-база должна быть пустой; разрешены только нетронутые начальные singleton-настройки. Если приложение уже создало в ней каталог предметов, используйте другую пустую базу: переносчик намеренно отказывается затирать существующие данные.

Перед переносом остановите запись в исходную SQLite-базу и сохраните её копию. Подготовка схемы не добавляет предметы или демонстрационные данные:

```bash
npm run db:init:postgres
npm run db:migrate:postgres -- --from data/smena.sqlite
npm start
```

Переносчик создаёт согласованный снимок SQLite с учётом WAL, проверяет целостность и переносит все 33 таблицы данных в одной транзакции. Идентификаторы, порядок записей, ревизии, пароль администратора, сессии, планы, настройки, опубликованные снимки, история замен и результаты повторных запросов сохраняются. Для каждого столбца идентификаторов и порядка обновляются последовательности. Перед фиксацией сверяются количество строк и SHA-256 каждой таблицы. Ошибка останавливает перенос и откатывает строки целевой базы; исходный файл не изменяется.

Порядок SQLite `rowid` сохраняется в отдельных `insertion_order`, включая пропуски после удалений. Текстовые идентификаторы в PostgreSQL используют `COLLATE "C"`, чтобы порядок выборок совпадал со SQLite независимо от локали самого сервера. PostgreSQL ведёт отдельный журнал миграций; прежние миграции SQLite не повторяют преобразования над перенесёнными данными.

Сохраняются и задания генерации. При старте приложения незавершённые задания помечаются прерванными: вычислявшие их процессы не переносятся вместе с базой.

- В браузере открылись публичное расписание, административное расписание, планы, замены, общие настройки и страница учителя; ошибок JavaScript не обнаружено. Школьные записи при проверке не изменялись.

Числовые результаты: [postgres-check-20261016.json](postgres-check-20261016.json). Снимок административного расписания: `artifacts/postgres-schedule-20261016.png`.

Для интеграционных проверок используется отдельная база `smena_pg_verify`, URL задаётся в `SMENA_TEST_DATABASE_URL`:

```bash

```

Каждый сценарий создаёт и удаляет только собственную временную схему. Основная база `smena` и публичная схема проверочной базы не очищаются. Без тестового URL тесты явно пропускаются.

## Архив школьных данных

В «Общие настройки → Перенос данных» доступны выгрузка и загрузка архива `.smena.gz`. Это gzip-архив с описанием формата и данными 31 таблицы приложения. Он включает настройки школы и историю. При восстановлении локальные логин и пароль администратора сохраняются, а сеансы сбрасываются.

Загрузка принимает файлы до 128 МиБ. Приложение проверяет совместимость версии формата, основной версии PostgreSQL, схемы и приложения; перед заменой показывает сведения об архиве и требует явного подтверждения. Выполняющаяся генерация блокирует восстановление. Перед заменой сохраняется резервная копия в `backups/restore` с правами только владельца. Изменение данных выполняется транзакционно и откатывается при ошибке. Пользователь PostgreSQL, под которым запущено приложение, должен иметь право создавать схемы в базе.

Команды `db:backup` и `db:restore` остаются для прежнего SQLite-контура и не выгружают PostgreSQL. Эксплуатационные шаги: [operations.md](operations.md).

Деплой выполняется последним шагом. Предусмотрены два варианта: самостоятельный Docker Compose и включение в общий пул `/home/rest/proj/app-docker-container`. На этом этапе файлы и контейнеры общего пула не менялись.
