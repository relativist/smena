# Руководство оператора

Краткая инструкция по запуску школьного расписания, повседневной работе и резервному копированию.

## Запуск

Нужны Node.js 24 LTS или совместимая более новая версия и npm.

Создайте отдельную базу PostgreSQL 18 и пользователя. Скопируйте `.env.example` в `.env.local` и укажите `SMENA_DATABASE_URL`; локальный файл с паролем исключён из Git. При старте приложение создаёт недостающую схему и начальные предметы, не перезаписывая уже настроенную школу.

Для разработки запустите интерфейс и API вместе:

```bash
npm ci
npm run dev
```

Откройте <http://127.0.0.1:5173>. Интерфейс доступен на порту 5173, API — на 3001. Для обычной локальной проверки этого достаточно.

Для собранного приложения:

```bash
npm ci
npm run build
npm start
```

Откройте <http://127.0.0.1:3001>. Сервер отдаёт готовый интерфейс и API. `npm run preview` служит для просмотра сборки Vite и не заменяет `npm start`.

На главной нажмите «Администратору» или откройте `/admin`; при первом входе задайте логин и пароль администратора (не менее 8 символов). Отдельного готового пароля нет. Новая PostgreSQL-база содержит 25 школьных предметов. Группы, преподаватели, кабинеты и расписание создаются администратором; демонстрационные записи не загружаются. При переносе прежней SQLite-базы сохраняются существующие учётная запись и данные школы.

## Рабочий цикл

После входа откройте **Документацию** в левой панели расписания. Встроенное руководство `/documentation` содержит порядок настройки школы и примеры использования основных возможностей; ученикам и публичной странице учителей оно не показывается.

1. В **Справочниках** проверьте или заполните группы, преподавателей и кабинеты. Уточните предметы и их требования к кабинетам. Готовые предметы уже есть в общем наборе; дополнительные можно добавить вручную.
2. В **Календаре школы** создайте четверть. В **Учебных планах** задайте группам предметы и количество часов. Это определяет, какие занятия нужны при составлении.
3. В **Календаре школы** укажите учебные дни и каникулы. В настройках звонков проверьте начало дня, длительность уроков и перемены. Название школы и показ значков задаются в **Настройки → Общие настройки**; название появится также на публичных страницах и в печати без повторной публикации.
4. В **Автосоставлении** выберите группы и четверть. Просмотрите предложенные занятия, недобор и конфликты; при необходимости скорректируйте параметры и составьте повторно.
5. Проверьте расписание по неделям: преподавателей, кабинеты, общие занятия и предупреждения. Внесите ручные изменения и дождитесь сохранения черновика.
6. Опубликуйте проверенную четверть. Ученики увидят опубликованный вариант на главной странице `/`; черновик публично не показывается.
7. Откройте **Печать расписания**, выберите опубликованный вариант и нужные группы, затем проверьте предпросмотр и распечатайте листы А4 или сохраните их в PDF.

Для обычной замены откройте страницу замен, выберите четверть, группу и предмет; при необходимости ограничьте выбор текущим преподавателем. Нажмите **Заменить преподавателя**, укажите даты и **Нового преподавателя**. Если менять нужно только отдельные занятия, включите **Назначить по урокам** и выберите преподавателя в нужных строках. Для передачи без конечной даты явно включите режим без конечной даты.

Для автоматического подбора на период отсутствия сначала сохраните период недоступности преподавателя в справочнике. На странице замен раскройте **Подбор на время отсутствия**, выберите период отсутствия и нажмите **Найти заменяющих**. Диалог называется **Замены на время отсутствия**; перед применением проверьте предложенные назначения.

Даты конечного периода включаются. После конечной даты правило замены больше не действует, а существующие уроки за пределами периода остаются без изменений. Если преподаватель вернулся раньше, сначала сократите фактический период недоступности в справочнике, затем вручную измените нужные будущие уроки, неделю или период обычным способом.

## Где хранится база

Основное хранилище — PostgreSQL, подключение задаётся через `SMENA_DATABASE_URL`. Порт приложения — `SMENA_PORT` (по умолчанию 3001). Для локальной разработки используется уже работающий PostgreSQL 18 на `127.0.0.1:5432`. Инструкция переноса и проверок: [postgres-migration.md](postgres-migration.md).

Исходный SQLite-файл сохраняется для сверки и отката. `SMENA_DB_PATH` оставлен для явного запуска прежнего SQLite-контура и изолированных тестов. Команды резервного копирования ниже относятся только к SQLite.

## Архив PostgreSQL

Администратор может скачать или загрузить архив в **Общие настройки → Перенос данных**. Файл `.smena.gz` — gzip-архив школьных данных и истории. При загрузке приложение проверяет формат и совместимость с версиями PostgreSQL, схемы и приложения, затем показывает дату, школу и число групп, учителей, кабинетов и уроков. Для продолжения отметьте подтверждение полной замены.

В архив входят настройки школы и её история. Логин и пароль администратора установленной школы сохраняются; сохранённые сеансы сбрасываются, текущему администратору выдаётся новый сеанс. Перед заменой приложение создаёт резервную копию школьных данных в `backups/restore` с правами `0600`. Восстановление выполняется транзакцией: при ошибке изменения откатываются. Если в школе выполняется генерация расписания, сначала дождитесь её завершения. Загрузка ограничена 128 МиБ. Для учётной записи PostgreSQL приложения требуется право `CREATE` на базу данных для создания временных схем.

Если ответ о восстановлении потерялся, вернитесь в «Общие настройки»: приложение проверит сохранённый статус операции. Не запускайте повторную загрузку до проверки результата.

## Резервная копия SQLite

Создайте каталог для копий, если его ещё нет, затем укажите **новый** файл назначения:

```bash
mkdir -p backups
npm run db:backup -- --to backups/smena-2026-10-14.sqlite
```

По умолчанию источник — `SMENA_DB_PATH` или `data/smena.sqlite`. Можно указать его явно:

```bash
npm run db:backup -- --db data/school.sqlite --to backups/school-2026-10-14.sqlite
```

Копирование использует встроенный механизм SQLite и включает изменения, ещё находящиеся в WAL-файле; останавливать работающий сервер для этой команды не требуется. Файл проверяется на целостность, создаётся с закрытыми правами доступа. Каталог назначения нужно создать заранее. Команда откажется перезаписывать существующий файл и соседние файлы SQLite `-wal`, `-shm` или `-journal`.

Копия содержит учётные записи, расписание, планы, публикации, настройки и историю. Храните её как конфиденциальные школьные данные; не выкладывайте в общедоступные папки или репозитории.

## Проверка восстановления SQLite

Восстановление всегда создаёт отдельный файл и не перезаписывает существующую базу:

```bash
npm run db:restore -- --from backups/smena-2026-10-14.sqlite --to data/smena-restore-check.sqlite
```

Каталоги `backups/` и `data/` должны существовать. Путь назначения должен быть новым и не иметь соседних файлов `-wal`, `-shm` или `-journal`. Резервная копия проверяется до восстановления, а новый файл — после.

Запустите восстановленную копию отдельно, указав её путь и свободный порт:

```bash
SMENA_DB_PATH=data/smena-restore-check.sqlite SMENA_PORT=3030 npm start
```

В отдельном профиле браузера или приватном окне откройте <http://127.0.0.1:3030> и проверьте опубликованное расписание учеников, четверти и планы, страницы преподавателей, настройки и предпросмотр печати. Войдите с прежним логином и паролем; если сохранённый сеанс истёк, войдите заново. Не указывайте рабочий файл базы в качестве места восстановления и не подменяйте им активную базу.

## Отдельная масштабная проба PostgreSQL 18

Укажите в `.env.local` отдельное тестовое подключение `SMENA_TEST_DATABASE_URL`. Команда использует только его, создаёт новую схему `smena_trial_<pid>_<uuid>` и не заменяет рабочую школу:

```bash
npm run trial:prepare:postgres
```

Результат содержит каталог временных файлов, логин и пароль пробного администратора. В каталоге сохраняются контекст, исходный снимок и `.env.local` с подключением только к созданной схеме. Файлы доступны владельцу (`0600`), каталог — `0700`. В PostgreSQL-пробе ровно 40 групп, 50 учителей, 24 кабинета и планы на 4 800 уроков; исходных демонстрационных групп SQLite нет.

Подставьте выведенный каталог вместо примера и откройте отдельный сервер на порту 3030:

```bash
SMENA_PORT=3030 node --env-file-if-exists=.env.local --env-file=/tmp/smena-trial-scale-example/.env.local server/index.ts
```

Последний env-файл задаёт подключение пробной школы. Откройте <http://127.0.0.1:3030/schedule> в отдельном профиле браузера, войдите под пробным администратором и выберите четверть «Проба · 40 групп». Проверьте генерацию, очистку и пересчёт одной группы, публикацию, публичные просмотры и печать. После пробы сначала остановите её сервер, затем удалите именно её каталог и схему:

```bash
npm run trial:cleanup:postgres -- /tmp/smena-trial-scale-example
```

Очистка проверяет контекст, имя созданной схемы и соответствие тестовой базы. Она не использует рабочее подключение `SMENA_DATABASE_URL` и не удаляет всю базу PostgreSQL. Схемы автоматических тестов удаляются самими тестами.

## Отдельная масштабная проба SQLite

Команда ниже подготавливает **новую временную базу** в системном временном каталоге:

```bash
npm run trial:prepare
```

Она выводит полный путь к базе, логин и пароль администратора пробной школы. Сохраните эти данные только для локального теста; при завершении временную базу можно удалить средствами операционной системы.

Набор включает исходные демонстрационные данные и добавляет 40 тестовых групп (7-е и 8-е классы), 50 преподавателей, 24 кабинета и четверть 7 октября — 1 ноября 2030 года. Для новых групп заведены планы по пяти предметам: расчётный объём — 120 уроков на группу, 4 800 суммарно. Расписание этой четверти предназначено для пробного заполнения и просмотра; данные набора не являются настоящими школьными записями.

Чтобы открыть эту базу отдельно, скопируйте выведенный путь и запустите сервер, например:

```bash
SMENA_DB_PATH=/tmp/smena-trial-scale-example/school.sqlite SMENA_PORT=3030 npm start
```

Фактический путь возьмите из результата `trial:prepare`; пример выше — только форма команды. Выберите четверть **«Проба · 40 групп»** и проверяйте новые группы с префиксами `7` и `8`. Не используйте эту базу как рабочую и не путайте группы примера 5А, 5Б и 6А с тестовыми.

Подготовка создаёт отдельную пробную школу и не меняет настроенную рабочую базу. Текущая версия автосоставления рассчитывает расписание в отдельном worker сервера; браузер показывает прогресс, позволяет отменить расчёт и применить результат. Скорость расчёта зависит от процессора сервера, сохранение — также от базы данных; отзывчивость интерфейса зависит от устройства пользователя. Эти операции нужно отдельно проверить в рабочем окружении.

## Проверки проекта

```bash
npm run check
npm test
npm run build
npm run test:postgres
```

Для PostgreSQL-проверок задайте `SMENA_TEST_DATABASE_URL`. Они создают собственные временные схемы, включая связный школьный сценарий и перенос архивов.

Эти команды проверяют типы, автоматические сценарии и сборку приложения. Они используют тестовые данные, а не подменяют проверку восстановления резервной копии.
