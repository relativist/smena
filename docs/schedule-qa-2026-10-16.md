# Проверка главной страницы расписания — 16 октября 2026

## Результат

**Обновление после исправления:** [SCH-001 исправлен и повторно проверен](schedule-bugs-2026-10-16.md). На одинаковом сценарии медиана открытия урока снизилась с 344 до 131 мс, смены кабинета — с 277 до 57 мс. С CPU ×4 — с 1 092 до 200 мс и с 983 до 80 мс соответственно. Доступность вариантов до/после совпала в 20 состояниях формы; профильные тесты, сборка и повторная функциональная проверка прошли. [Числа повторного прогона](schedule-dialog-fix-2026-10-16.json).

Далее сохранён **первичный отчёт до исправления**. Загрузка расписания и повседневные переключения на проверенной машине работали быстро. Открытие окна урока и изменение кабинета вызывали заметную блокировку браузера; поэтому в первичном прогоне подтвердить отсутствие тормозов было нельзя.

В проверенных основных сценариях потери данных и ошибок сохранения не обнаружено. Серверные чтения также работают быстро. Код приложения не изменялся.

Рабочие данные тестовыми действиями не менялись: после проверки ревизия по-прежнему 448, версия настроек 8, количество групп/учителей/кабинетов/уроков совпало с исходным. Тестовый сервер остановлен, отсутствие временной схемы PostgreSQL проверено отдельно.

## Условия и метод

- Код `a24c2e6`, локальная собранная версия, Chromium через Playwright CLI, локальное тестовое окружение.
- Копия текущей **PostgreSQL** через согласованный архив: ревизия 448, 74 группы, 131 учитель, 177 кабинетов, 181 328 уроков. Тестовый сервер доступен только локально; отдельная временная схема без доступа через `search_path` к рабочим таблицам.
- Основные замеры: окно 1440×1000, по 5 повторных загрузок обычно и с CPU браузера ×4, всего 162 измеренных действия. Переключались параллели 1/5/10/11, варианты классов и недели. Браузерный таймер отсчитывает действие до готовности данных и двух кадров `requestAnimationFrame`; накладные расходы автоматизации включены.
- Это локальный HTTP, прогретый браузер и тот же компьютер для сервера. CPU ×4 замедляет браузер, но не PostgreSQL и не сервер; это не измерение на школьном компьютере. Холодный старт с пустым кешем, медленная внешняя сеть и длительная многопользовательская нагрузка отдельно не проверялись.
- Для тестовой схемы после заполнения синхронизированы identity-последовательности. Первый служебный запуск до этой подготовки получил конфликт `schedule_slots_pkey` и исключён из приёмочных результатов. Это ошибка подготовки копии: штатный `restorePrepared` сам перезапускает последовательности. Продуктовым багом она не зарегистрирована.

## Производительность браузера

Миллисекунды, округление до целых. Для переключений и открытия окна по 12 измерений на режим CPU; недель — по 9; смены кабинета — по 4.

| Сценарий | Обычный CPU: медиана / максимум | CPU ×4: медиана / максимум |
| --- | ---: | ---: |
| Повторная загрузка до готового расписания | 257 / 264 | 608 / 624 |
| Выбор параллели | 145 / 174 | 364 / 442 |
| Выбор варианта класса | 171 / 196 | 412 / 478 |
| Выбор предмета | 96 / 182 | 196 / 266 |
| Выбор карточки преподавателя, до появления режима размещения | 99 / 113 | 173 / 246 |
| Отмена выбора карточки | 83 / 101 | 232 / 304 |
| Переключение недели | 172 / 221 | 339 / 420 |
| Открытие окна урока | **360 / 396** | **1 174 / 1 316** |
| Изменение кабинета в окне урока | **340 / 359** | **1 303 / 1 308** |

Отдельный связный сценарий: выбор карточки **до завершения проверки мест** — 204 мс, HTTP 200, 35 проверенных ячеек. Правка примечания до «Сохранено» — 617 мс; добавление урока до «Сохранено» — 553 мс. Эти два времени включают штатную паузу автосохранения 350 мс, а не только выполнение запроса. Здесь по одному измерению, это не статистика p95.

В обычном режиме при измеренных переключениях параллелей, вариантов, предметов и недель задач дольше 50 мс не зафиксировано. Окно урока выделяется задачами до 310 мс, с CPU ×4 — до 1 214 мс. В серии 162 действий ошибок JavaScript не было.
